# Система для проверки OpenGraph разметки

Система предназначена для проверки валидности OpenGraph разметки в первую очередь в тестовом/локальном окружении.

## Возможности системы

Система должна иметь возможность работать в двух режимах

1) Режим локальной проверки
2) Режим фактической серверной проверки

### Режим локальной проверки

В режиме локальной проверки происходит проверка сайта по заданному заранее набору параметров. Пользователь должен иметь возможность настраивать социальные сети, для которых он хочет проверить разметку — набор проверяемых тегов и правил для каждой соцсети задаётся через конфиг (см. раздел «Конфигурация проверки»).

Расширение можно глобально включать/выключать переключателем (ползунком) — в popup и/или на странице настроек. В выключенном состоянии проверки не выполняются, badge серый. Состояние сохраняется в `storage`.

Область проверки настраивается через один из трёх взаимоисключающих режимов (белый и чёрный списки не используются одновременно):

1) **Только текущий домен** — проверяется лишь домен активной вкладки.
2) **Все, кроме списка (чёрный список)** — проверка на всех сайтах, кроме перечисленных; пустой список = проверять везде.
3) **Только из списка (белый список)** — проверка только на перечисленных доменах.

Списки поддерживают wildcard/поддомены/порты (важно для `localhost`). Настройки хранятся в `storage`.

Результат проверки имеет три уровня: `ok`, `warning`, `error`. Индикация состоянием badge на иконке расширения:

- **серый** — проверка выключена / не выполнялась;
- **синий** — проверка в процессе;
- **зелёный** — всё ок (`ok`);
- **жёлтый** — есть замечания (`warning`);
- **красный** — критичные проблемы (`error`).

В popup выводится детальный отчёт: какие теги в порядке, каких не хватает, список замечаний и ошибок.


### Режим фактической серверной проверки

Смысл режима: краулеры соцсетей не видят `localhost` и часто не исполняют JS. Поэтому расширение снимает **готовый отрендеренный HTML страницы (после исполнения JS)** и отправляет его на серверную часть, которая раздаёт его по публичному URL — так можно проверить, как реальный краулер увидит разметку. Адрес сервера задаётся в настройках расширения.

**Сохранение картинок.** Чтобы `og:image` были доступны краулеру, картинки могут сохраняться на сервере. Режим сохранения настраивается (3 варианта):

1) **Сохранять все og-картинки** — все изображения из OG-тегов сохраняются на сервер, ссылки переписываются на публичные.
2) **Сохранять только недоступные** — сохраняются только локальные/недоступные извне картинки (например, лежащие на `localhost`); картинки на сторонних ресурсах, доступные публично, не трогаем.
3) **Не сохранять** — раздаётся только HTML, ссылки на картинки остаются как есть.

**Таймер.** Сервер возвращает публичную ссылку, которая отображается в расширении вместе с таймером на 15 минут — столько по умолчанию хранится статика (TTL в Redis). Должны быть кнопки продлить время и принудительно остановить сессию. По ссылке на статус сервер отдаёт состояние сессии: идёт ли таймер и сколько осталось. Состояние живёт на сервере; расширение при открытии popup восстанавливает его по session id из `storage`, поэтому оно сохраняется при перезагрузке страницы.

**Аутентификация.** Реализуется через куку владельца сессии: продлевать и завершать сессию может только её владелец. Раздаваемая статика изолируется (отдельный домен/поддомен, заголовки CSP, корректный `Content-Type`), вводятся лимиты на размер загрузки и rate limiting.


## Конфигурация проверки

Набор проверяемых тегов и правил задаётся через конфиг. Для каждой соцсети — свой профиль (свой конфиг), что позволяет расширять список соцсетей без изменения кода. Профиль описывает: обязательные теги (их отсутствие → `error`), рекомендуемые теги (отсутствие → `warning`) и дополнительные правила (непустое значение, доступность `og:image` по URL, минимальные размеры картинки и т.п.).

Базовый набор OpenGraph-тегов:

- **Обязательные:** `og:title`, `og:type`, `og:image`, `og:url`.
- **Рекомендуемые:** `og:description`, `og:site_name`, `og:locale`.
- **Для изображения:** `og:image:width`, `og:image:height`, `og:image:alt`.

Профили соцсетей (уточняются в конфиге):

- **Facebook / WhatsApp:** базовый OG + `fb:app_id` (рекомендуемо); `og:image` желательно ≥ 200×200, оптимально 1200×630.
- **VK:** базовый OG; проверка доступности и размеров `og:image`.
- **Telegram:** базовый OG (`og:title`, `og:description`, `og:image`).
- **Twitter / X:** `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image` (с фолбэком на `og:*`).
- **LinkedIn:** `og:title`, `og:type`, `og:image`, `og:description`, `og:url`.

Пример структуры профиля (ориентир, финализируется в коде):

```json
{
  "facebook": {
    "required": ["og:title", "og:type", "og:image", "og:url"],
    "recommended": ["og:description", "og:site_name", "fb:app_id"],
    "rules": {
      "og:image": { "reachable": true, "minWidth": 200, "minHeight": 200 }
    }
  }
}
```

## Состав системы

Система состоит из двух частей - расширения для браузера (Chrome, Firefox) и серверной части.
Серверная часть должна содержать базу данных с данными сессий и бэкэнд.

## Выбор технологий

1) Расширение — JS, Manifest V3, `webextension-polyfill` для кросс-браузерности (Chrome, Firefox).
2) Серверная часть — Node.js + **Express** (обязательный компонент). Раздача статики, CSP (`helmet`), лимиты размера и rate limiting (`express-rate-limit`) реализуются на уровне приложения.
3) База данных — Redis (эфемерные сессии с TTL; при очистке данных не критично).
4) **Reverse proxy — опционален**, добавляется на этапе публичного деплоя, когда нужны:
   - публичный HTTPS (краулеры FB/LinkedIn работают по `https`);
   - изоляция раздаваемой чужой статики на отдельном домене/поддомене от API с кукой владельца.
   Рекомендуемый вариант — **Caddy** (авто-TLS через Let's Encrypt, минимальный конфиг); nginx — как альтернатива. Для локальной разработки/MVP прокси не нужен. Альтернатива для тестирования localhost-страниц — туннель (cloudflared/ngrok), дающий публичный HTTPS-URL без отдельного прокси.
5) Контейнеризация — Docker + docker-compose (Express + Redis; reverse proxy добавляется в compose на этапе деплоя) для простоты развёртывания и масштабирования.

## Открытые вопросы (уточняются при реализации)

1) Финальные пороги размеров `og:image` и точный состав тегов в профилях соцсетей — фиксируются в конфиге.
2) Формат хранения списков доменов и синтаксис wildcard.
3) Схема изоляции публичной статики (отдельный поддомен vs путь) и конкретные CSP-заголовки.
